## Challenge Overview
- **Category:** Forensics / Reverse Engineering
- **Provided Files:**
  - `checkpoint.tar` (containing CRIU images: `files.img`, `ghost-file-1.img`, `pagemap-8.img`, `pages-2.img`, `sk-queues.img`, `mm-8.img`, etc.)
  - `relay` (stripped ELF 64-bit x86-64 binary compiled with Go)
  - `README.md`, `TOOLS.md`, `SHA256SUMS`

## Description & Hints
> Operations believes the process still held one sealed incident record that never reached storage.
> 
> Inspect the checkpoint and recover the exact record.
> 
> Submit the single `zdk{...}` value recovered from the incident record.
> 
> The checkpoint does not need to be restored. The queued socket packet is a compact `QMSG` structure whose pointer can be translated through the captured pagemap; the deleted ghost file begins with an `IRF1` record.

## Technical Analysis

### 1. Reverse Engineering the `relay` Binary
Using Go's `pclntab` located in the stripped binary, we uncovered the non-runtime function symbols:
- `main.marshalQueue` (`0x4a3c60`)
- `main.deriveIncidentKey` (`0x4a3d40`)
- `main.xorStream` (`0x4a3e40`)
- `main.selfTest` (`0x4a3fa0`)
- `main.main` (`0x4a45e0`)

Disassembling these functions revealed the exact cryptographic schemes used:

1. **State Serialization (`RelayState`)**:
   A 120-byte struct containing:
   - `+0x00`: Version/type metadata
   - `+0x10`: Payload length
   - `+0x18`: `hash1` (State label hash, 32 bytes)
   - `+0x38`: `port_hash` (Port digest, 32 bytes)
   - `+0x60`: `hash2` (Incident key label hash, 32 bytes)

2. **Packet Structure (`QMSG`)**:
   100-byte structure serialized in `sk-queues.img`:
   - `0x00 - 0x04`: Magic `QMSG`
   - `0x04 - 0x08`: Version (`2`) & reserved fields
   - `0x08 - 0x18`: Cluster ID (16 bytes)
   - `0x18 - 0x20`: Pointer to state in process memory (`0x7f604a43f000`)
   - `0x20 - 0x40`: `port_hash` (`SHA256(cluster_id || state_hash || "port")`)
   - `0x40 - 0x60`: `starboard_hash` (`SHA256(cluster_id || state_hash || "starboard")`)
   - `0x60 - 0x64`: Castagnoli CRC32 (`CRC32-C`) of the preceding 96 bytes

3. **Key Derivation Function (`main.deriveIncidentKey`)**:
   $$\text{DerivedKey} = \text{SHA256}(\text{KeyHash}_{32} \mathbin{\Vert} \text{ClusterID}_{16} \mathbin{\Vert} \text{Prefix}_8)$$

4. **Stream Decryption (`main.xorStream`)**:
   A counter-mode keystream generated by hashing the derived key with a 32-bit little-endian block index:
   $$\text{Keystream Block}_i = \text{SHA256}(\text{DerivedKey} \mathbin{\Vert} \text{LE32}(i))$$
   $$\text{Plaintext} = \text{Ciphertext} \oplus \text{Keystream}$$

### 2. Extracting Artifacts from CRIU Images

#### A. Queued Socket Packet (`sk-queues.img`)

#### B. Deleted Ghost File (`ghost-file-1.img`)
The deleted ghost file (formerly `/tmp/.relay-case-LM-a3febe5e3ae7`) begins with an `IRF1` record:
- **Magic & Header Length:** `IRF1`, header size `40` bytes (`0x28`)
- **Cluster ID:** `46c3123bf4142d5162fae3a5d2002777`
- **Record Prefix (bytes 24-32):** `68234cba61a9ff0d`
- **Encrypted Payload:** 167 bytes (offset 40 to 207)

### 3. Decryption & Flag Recovery

Using the recovered values:
- `KeyHash`: `197e6a2680c14b237794362581aad4247b0cf08f735c6aed268c0ac7ac5a4622`
- `ClusterID`: `46c3123bf4142d5162fae3a5d2002777`
- `Prefix`: `68234cba61a9ff0d`

We computed:
$$\text{DerivedKey} = \text{SHA256}(\text{KeyHash} \mathbin{\Vert} \text{ClusterID} \mathbin{\Vert} \text{Prefix})$$

Applying `xorStream` to the 167-byte payload in `ghost-file-1.img` yielded:
```text
INC15\x00zdk{cRIU_4FT3riM4G3_soa7etEZoBLOb3Tbcdqgl850cqddS9ca}...
```
